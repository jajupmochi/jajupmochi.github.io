## 口吻与文风

- **技术博客口吻，自然、个人化**。像一个真正动手做过的人在分享，而不是文档生成器。
- **去 AI 化**：不要废话、不要铺垫客套、不要注水过渡、不啰嗦。一句话不增信息就删。
  （Linlin 反复强调："文风去 AI 化"、"有点 ai 且啰嗦"。）
- **以问题开头**，第一人称、贴近读者。fcitx5 那篇的开头："我之前一直在 Ubuntu 上用搜狗，但是……"。先讲痛点，再讲解法。
- **从真实体验解释"为什么"**，而非只讲"是什么"。例：说明为何选 Wayland 而非 Xorg —— 作者实测前者明显更流畅（文件管理器、浏览器、IDE），而不是空泛断言。
- 用户可见文案不用破折号（全站规则）；emoji 仅在确有含义时使用。

## 结构

- **多层目录**。大框架一目了然、易扫读；读者能快速定位任意部分。
- 在骨架之下，正文**极其详细** —— 每条命令、依赖、片段、步骤、坑都写清楚。

## 可复现

- 读者应能**无脑复制粘贴、照着走**到同样结果。我们真实流程里的每条命令、依赖、代码、操作，按顺序、连同真正重要的细节一并写入。
- 用可直接复制的围栏代码块（博客渲染器为每块提供语言标签 + 复制按钮）。

## 详述自家设计而非只有步骤

- 详述**我们自己的配置和设计**：改了什么、**为什么**（原理）、在**哪里**（确切文件 / 代码 / 位置）。
- 覆盖用到的**资源**及其**制作方式** —— 例如奔跑的小狗是"Claude Code 初稿 + Claude design 优化"；字体；UniBE 颜色来源及我们的改动。
- **打包 / 指明每一项资源**。若某资源需单独插入或引用，明确说明并请 Linlin 确认 / 提供，不要凭空捏造。

## 给 AI agent 的便利

- **开头给一段 AI 提示词**，读者可直接粘贴给 AI agent 来跑完整教程。
- 加一段**写给 AI agent**的话，让它直接读文章 URL（或粘贴其余部分），使文章本身成为 agent 可执行的脚本。
- 教读者**自行复刻定制**：先列出哪些可配置（资源、背景色、字体、我们做过的每处改动），再讲每处怎么改。写得让 AI agent 能直接照做，并说明。

## 作者与人称

- **每处人称都区分人类作者与 Claude**。署名为人类作者 + "Claude Code (Opus 4.7)"。
- 人类特有事实用"本文的人类作者"表述：例如不写"我在伯尔尼大学念书"，而写"本文的人类作者此时在伯尔尼大学工作"。
- 作者状态如实标注（见 registry 的 `translationStatus` 阶梯：`ai` / `ai_edited` / `checked` / `human`）。AI 起草、人工编辑但未审阅 = `ai_edited`，展示为"AI 起草 · 人工编辑 · 未审阅"。

## 图与示意图

- **封面图 —— 必需、内容对应**。每篇文章都要在 `blog-posts/registry.json` 的
  `cover` 字段配一张封面（路径相对文章目录，如 `cover.webp` 或 `assets/x.png`），
  它会显示在博客列表 / 卡片上。没有封面不算完成。封面必须是文章**自身**主题的
  截图或剪裁 —— 即这篇文章讲的功能、界面、结果或素材 —— 不用泛用的素材图。默认
  规则：**但凡能找到合适的图，就加上**。
- **内文图 —— 至少一张，放在展示该功能处**。在正文里讲到那个界面 / 结果的地方，
  另起一行放 `![描述性 alt](file.webp)`（上下各空一行）。`blog.js` 会把相对 `src`
  改写到 `blog-posts/<slug>/`，所以只写文件名即可。同一张图要同时加到 `en.md` 和
  `zh.md`，alt 翻译对应。
- **怎么做一张**。在浏览器里截真实功能，裁掉浏览器外框（导航栏），转成约 16:10 的
  WebP：`convert shot.png -crop WxH+X+Y +repage -resize 820x -quality 85 cover.webp`
  （ImageMagick）。只有格式需要时（如动图）才用 PNG / GIF。
- **全程图文并茂**。复用工作中真实的截图（有助理解时），放在对应步骤旁。
- **架构 / 流程图用 Mermaid 或 SVG**，在文中编写（渲染器支持 ` ```mermaid ` 围栏块），不用位图 mockup。

## 双语交付

- **中英各一文件**（`blog-posts/<slug>/zh.md` + `en.md`），在 `blog-posts/registry.json` 注册。
- 目标平台为本站博客**和**知乎 —— 文案保持可移植到两边。

## 检查清单

一篇文章"完成"前确认：

- [ ] 问题先行、第一人称开头
- [ ] 多层目录 + 可扫读结构
- [ ] 每条命令 / 依赖 / 步骤可复制、按顺序
- [ ] 我们的配置 + 设计选择已记录（什么 / 为什么 / 在哪）
- [ ] 所有资源已包含或明确标记请 Linlin 提供
- [ ] "如何自己做"一节（先列可配项，再讲怎么做）
- [ ] 顶部 AI 提示词 + 给 agent 读 URL 的一段
- [ ] 人类作者 vs Claude 处处区分
- [ ] registry 里配了封面（`cover`）、内容对应、WebP；能在博客列表显示
- [ ] 至少一张内文截图，en + zh 同图，放在展示该功能处
- [ ] 示意图用 Mermaid / SVG；相关截图就近放置
- [ ] zh + en 文件已注册；`translationStatus` 如实
- [ ] 去 AI 化：无废话、不啰嗦、无破折号、无装饰性 emoji
